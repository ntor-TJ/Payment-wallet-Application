# Payment Wallet Application

A Java Spring Boot REST API application that provides basic
digital-wallet functionality. Customers can register and log in, link
bank accounts, add money to a wallet, transfer money to another
customer, manage beneficiaries, pay bills, and redeem cashback
promotions.

## Project overview

The application uses a layered Spring Boot structure:

``` text
Postman / REST Client
        |
        v
Spring Boot Controllers
        |
        v
Service Layer (business logic and validation)
        |
        v
Spring Data JPA / Hibernate
        |
        v
MySQL Database
```

-   **Controllers** expose REST endpoints and handle HTTP requests.
-   **Services** implement application rules, including balance checks
    and wallet operations.
-   **Entities** represent database records such as customers, wallets,
    bank accounts, bills and transactions.
-   **Spring Data JPA / Hibernate** provide object-relational
    persistence.
-   **MySQL** stores application data.

## Features

### 1. Customer registration and login

-   Register a customer.
-   Create a wallet for a newly registered customer when one is not
    supplied.
-   Start a customer session through login.
-   Use the returned session key for wallet operations.

Endpoints used:

``` http
POST /customer
POST /login
PATCH /logout?key={sessionKey}
```

### 2. Bank account management

-   Add a bank account and associate it with a wallet.
-   Retrieve bank accounts associated with a wallet.
-   Use the generated account number in wallet funding requests.

Endpoints used:

``` http
POST /banks/{walletId}?key={sessionKey}
GET  /wallet/{walletId}
```

Example request body for creating a bank account:

``` json
{
  "ifscCode": "SBIN0001234",
  "bankName": "State Bank",
  "balance": 5000
}
```

The `accountNo` is generated by the application. The wallet is
associated through the wallet ID in the URL.

### 3. Add money to wallet

-   Validate the customer session.
-   Find the bank account and verify that it belongs to the customer's
    wallet.
-   Check that the bank account has sufficient funds.
-   Debit the bank account and credit the wallet.
-   Record the wallet transaction.

``` http
POST /addmoney/{amount}/{accountNo}?key={sessionKey}
```

Example:

``` http
POST /addmoney/500/21?key={sessionKey}
```

No request body is required for this endpoint.

### 4. Deposit money from wallet to bank

The application also exposes a wallet-to-bank deposit operation:

``` http
POST /depositmoney/{amount}/{accountNo}?key={sessionKey}
```

### 5. Wallet-to-wallet fund transfer

-   Identify the source customer from the session.
-   Validate that the supplied source mobile number matches the
    logged-in customer.
-   Find the receiver using the receiver's mobile number.
-   Reject invalid transfers such as same-wallet transfers or
    insufficient balance.
-   Debit the source wallet and credit the receiver wallet.
-   Create transaction records for both sides of the transfer.

``` http
POST /fundtransfer/{amount}/{sourceMobile}/{targetMobile}?key={sessionKey}
```

Example used during testing:

``` http
POST /fundtransfer/100/9876543215/9876543211?key={sessionKey}
```

The service method uses `@Transactional` so the related database updates
are handled within a transaction.

### 6. Wallet balance inquiry

Retrieve the balance of the wallet associated with the logged-in
session:

``` http
GET /showbalance?key={sessionKey}
```

### 7. Beneficiary management

The application provides endpoints to add, view and delete
beneficiaries, and to view all beneficiaries for a customer.

``` http
POST   /wallet/addbeneficiary
GET    /wallet/viewbeneficiary/{mobileNumber}
POST   /wallet/viewallbeneficiary
DELETE /wallet/deletebeneficiary
```

The add and delete operations maintain the relationship between
beneficiary details and the wallet. The delete request expects a
beneficiary request body as defined by the API.

### 8. Bill payment

-   Check the wallet balance.
-   Deduct the bill amount from the wallet.
-   Save the bill payment details.
-   Generate and store a promotional cashback code.

``` http
POST /bills/{walletId}
```

Example:

``` http
POST /bills/19
```

Request body:

``` json
{
  "amount": 100,
  "billType": "Electricity"
}
```

A successful bill-payment response provides the promotional code needed
for cashback redemption.

### 9. Cashback redemption

-   Submit the bill ID, wallet ID and promotional code.
-   Validate the promotional code.
-   Calculate the cashback amount.
-   Credit the cashback to the wallet.

``` http
GET /cashback/{billId}/{walletId}?promocode={promoCode}
```

Example format:

``` http
GET /cashback/28/19?promocode={promoCode}
```

Use the actual bill ID and promo code returned by the bill-payment flow.

## Local setup

### Prerequisites

Install or configure:

-   JDK compatible with the project's Spring Boot version
-   Maven
-   MySQL (local installation or Docker)
-   Postman

### 1. Clone the repository

``` bash
git clone https://github.com/JambojuEshwar/Payment-wallet-Application.git
cd Payment-wallet-Application
```

If the Spring Boot project is inside a subfolder, change into the
directory containing the `pom.xml` file before running Maven.

### 2. Configure MySQL

Create a MySQL database and configure the database connection in the
application's configuration file (usually
`src/main/resources/application.properties` or `application.yml`).

Set the database URL, username and password to match your local MySQL
setup. Do not commit real database passwords, API keys or other secrets
to GitHub.

### 3. Run the application

From the directory containing `pom.xml`:

``` bash
mvn spring-boot:run
```

The application used during the demo was available at:

``` text
http://localhost:8080
```

Keep the application running while sending requests from Postman.

## Testing with Postman

For endpoints that accept a session key:

1.  Register a customer using `POST /customer`.
2.  Log in using `POST /login`.
3.  Copy the session key from the login response.
4.  Pass it as the `key` query parameter in the relevant requests.
5.  For JSON request bodies, select **Body → raw → JSON** in Postman.
6.  Verify results using the API responses and, where appropriate, the
    MySQL records.

## Important implementation notes

-   Wallet operations use a session key returned by login.
-   Bank-to-wallet funding validates that the selected bank account
    belongs to the logged-in customer's wallet.
-   Fund transfers validate the source customer, receiver wallet and
    available balance.
-   Wallet-to-wallet transfer creates debit and credit transaction
    records.
-   Do not share session keys, passwords or database credentials in
    screenshots, source control or public documentation.
-   Use the actual API response when reporting the final wallet balance
    and cashback amount.
